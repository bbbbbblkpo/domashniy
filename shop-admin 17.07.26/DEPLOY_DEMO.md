# Временная закрытая демо-версия «Смены»

Это инструкция для показа преподавателю на временном адресе Render. Она рассчитана только на полностью вымышленные данные и не подготавливает публикацию для магазина. Render выдаст HTTPS-ссылку вида `https://имя-сервиса.onrender.com`; собственный домен для показа не нужен.

Сайт не появится в поиске благодаря `robots.txt`, метатегу и `X-Robots-Tag`, но это не пароль. Доступ к данным защищён входом и проверкой роли на сервере. Отправляйте ссылку только преподавателю и отдельно сообщите пароль только той демо-учётной записи, которую хотите показать.

## 1. Подключить приватный GitHub-репозиторий

Исходный код хранится в приватном GitHub-репозитории. Перед подключением проверьте, что у него есть ветка `main`, а в коммите нет `.env`, `data.db`, файлов `*.sqlite*`, резервных копий с данными или экспортов JSON. `.gitignore` исключает локальные секреты, базы и вложенные посторонние репозитории.

## 2. Создать сервис на Render

1. Откройте [Render Dashboard](https://dashboard.render.com/) и нажмите **New → Blueprint**.
2. Подключите GitHub, выберите приватный репозиторий с приложением и ветку `main`.
3. В поле **Blueprint Path** укажите `shop-admin 17.07.26/render.yaml`. Этот файл задаёт папку проекта как `rootDir`, где расположен Dockerfile.
4. Проверьте, что создаётся один веб-сервис `smeny-private-demo`, а PostgreSQL, Caddy и другие сервисы не добавляются.
5. В окне создания задайте значения для трёх запрошенных секретов: `DEMO_OWNER_PASSWORD`, `DEMO_ADMIN_PASSWORD`, `DEMO_EMPLOYEE_PASSWORD`. Придумайте три разных длинных пароля (лучше 20 символов и больше). На Mac можно отдельно запустить `openssl rand -base64 24` три раза и вставить результаты в поля Render. Не вставляйте их в GitHub, код, README или переписку с преподавателем.
6. `SECRET_KEY` Render создаёт автоматически. Остальные значения уже заданы в `render.yaml`: `DEMO_MODE=true`, `COOKIE_SECURE=true`, `APP_ENV=production`, SQLite в `/tmp` и проверка `/health`.
7. Нажмите **Apply** и дождитесь статуса **Live**. Первый запуск может занять несколько минут.

Render поддерживает `generateValue: true` для случайного `SECRET_KEY`, а для переменных с `sync: false` просит значение во время первоначального создания Blueprint. Эти правила описаны в [справке Render по Blueprint](https://render.com/docs/blueprint-spec). Состояние `/health` задаётся полем `healthCheckPath`; подробности есть в [справке Render о проверках здоровья](https://render.com/docs/health-checks).

Контейнер слушает `0.0.0.0:$PORT` (если Render не передал `PORT`, используется `10000`), как требует [справка Render по веб-сервисам](https://render.com/docs/web-services).

## 3. Получить ссылку и проверить вход

1. Откройте созданный сервис в Render. Ссылка `onrender.com` отображается на странице сервиса; откройте её в приватном окне браузера.
2. Проверьте, что адрес начинается с `https://`, появляется экран входа, а `/health` отвечает `{"status":"ok"}`.
3. Входы для демонстрации: `demo-owner`, `demo-admin`, `demo-employee`. Пароли — только те, которые вы задали в шагах выше.
4. После каждого старта контейнера демо-база создаётся заново. В ней только вымышленные сотрудники, смены недели 16–22 ноября 2026 года, авансы и заказы. Изменения во время показа временны и могут исчезнуть после перезапуска сервиса. Кнопка «Сбросить демо-данные» доступна владельцу.
5. В демо-режиме скачивание резервной копии и импорт недоступны. Приложение не читает локальную базу с Mac и игнорирует `DATABASE_URL`, если она задана платформой.

Free-сервис Render может засыпать после периода без запросов и может перезапускаться; его файловая система временная. Поэтому этот вариант подходит только для учебного показа. См. [ограничения Free-сервисов Render](https://render.com/docs/free) и [описание временной файловой системы](https://render.com/docs/faq).

## 4. Временно отключить после показа

1. В Render Dashboard откройте страницу сервиса.
2. В меню действий сервиса выберите **Suspend** и подтвердите. Пока сервис приостановлен, ссылка не обслуживает приложение.
3. Чтобы снова показать проект, выберите **Resume**. Для полного удаления сервиса откройте его **Settings** и выберите удаление сервиса. Render также описывает приостановку и возобновление сервисов в [справке Dashboard](https://render.com/docs/render-dashboard).

Не отправляйте преподавателю пароли владельца, если ему достаточно посмотреть интерфейс. Для проверки прав можно передать пароль администратора или сотрудника; после показа приостановите сервис и удалите его, если временная ссылка больше не нужна.
